# 外设中断测试说明

## 测试目标

测试 UART 外设中断功能，验证：

1. UART 能否正确触发外部中断
2. PLIC 能否正确分发中断
3. 中断处理函数能否正确响应 UART 中断

## 测试实现

### 1. 外设中断处理流程

```
用户键盘输入 → UART 硬件接收 → 产生 IRQ 10 中断 → PLIC 转发
→ CPU 接收外部中断 → trap_kernel_handler()
→ external_interrupt_handler() → uart_intr() 读取并回显字符
→ plic_complete() 通知中断完成
```

### 2. 代码修改

在 `kernel/trap/trap_kernel.c` 的 `external_interrupt_handler()` 中：

```c
void external_interrupt_handler()
{
    // 获取中断号
    int irq = plic_claim();

    if (irq == UART_IRQ) {
        // UART 串口中断
        printf("\n[External Interrupt] UART IRQ=%d detected\n", irq);
        uart_intr();  // 这个函数会读取并回显字符
        printf("[External Interrupt] UART interrupt handled\n\n");
    } else if (irq) {
        // 未知的外设中断
        printf("Unexpected external interrupt irq=%d\n", irq);
    }

    // 通知PLIC该中断已处理完成
    if (irq) {
        plic_complete(irq);
    }
}
```

### 3. 初始化流程

在 `kernel/boot/main.c` 中：

- 初始化 UART：`uart_init()`
- 初始化 PLIC：`plic_init()` 和 `plic_inithart()`
- 初始化 trap 系统：`trap_kernel_init()` 和 `trap_kernel_inithart()`
- 使能中断：`intr_on()`

## 验证要点

1. **中断触发**

   - 每次键盘输入都应触发中断
   - 不输入时不应有中断
2. **IRQ 号正确**

   - UART 的 IRQ 应该是 10
3. **字符回显**

   - 输入的字符应该被正确回显
   - 字符不应丢失或重复
4. **中断处理完整**

   - 每次中断都应该有开始和结束的提示信息
   - PLIC 应该正确完成中断确认

## 常见问题

### 1. 输入字符没有反应

- 检查 UART 是否正确初始化
- 检查 PLIC 是否正确配置
- 检查中断是否已使能（`intr_on()`）

### 2. 中断信息重复

- 这是正常的，因为有多个 CPU 核心同时处理中断
- 可以修改为只让 CPU 0 处理外设中断

### 3. 字符回显混乱

- 可能是多核并发导致
- 建议只使用单核测试（修改 Makefile 中的 CPUNUM=1）

## 注意事项

1. **时钟中断仍在后台运行**：虽然不输出，但 timer 仍在更新 ticks
2. **多核问题**：两个 CPU 都可能处理外设中断，可能看到重复输出
3. **退出方式**：必须用 `Ctrl+A` 然后 `X` 退出，直接 `Ctrl+C` 可能无法正确退出
