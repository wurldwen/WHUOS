# 中断处理函数调用说明

## 修改的文件

### 1. kernel/boot/start.c (M-mode 启动代码)

#### 添加的头文件

```c
#include "dev/timer.h"
```

#### 添加的函数调用

在 `start()` 函数中，在配置完物理内存保护后，添加：

```c
// 初始化时钟中断 (M-mode)
timer_init();
```

**调用位置**: 在 `w_pmpcfg0(0xf)` 之后，`w_tp(id)` 之前

**功能说明**:

- 设置 M-mode 时钟中断
- 配置 CLINT 寄存器
- 准备 mscratch 数组
- 使能 M-mode 时钟中断

---

### 2. kernel/boot/main.c (S-mode 主函数)

#### 添加的头文件

```c
#include "dev/uart.h"
#include "dev/plic.h"
#include "trap/trap.h"
```

#### CPU 0 的初始化序列 (主CPU)

在 `kvm_inithart()` 之后添加：

```c
// 初始化设备和中断系统
uart_init();              // 初始化UART串口
plic_init();              // 初始化PLIC中断控制器
trap_kernel_init();       // 初始化内核trap系统
trap_kernel_inithart();   // 初始化当前核心的trap
plic_inithart();          // 初始化当前核心的PLIC

// 使能中断
intr_on();
```

**初始化顺序说明**:

1. **uart_init()**: 配置串口硬件，必须在其他使用串口的代码之前
2. **plic_init()**: 设置 PLIC 全局配置（中断优先级等），只需 CPU 0 执行一次
3. **trap_kernel_init()**: 初始化内核 trap 全局资源（如系统时钟），只需 CPU 0 执行一次
4. **trap_kernel_inithart()**: 为当前 CPU 核心设置 trap 向量（stvec）
5. **plic_inithart()**: 为当前 CPU 核心使能 PLIC 中断
6. **intr_on()**: 开启当前 CPU 的中断

#### 其他 CPU 的初始化序列

在等待 `started` 变量后添加：

```c
// 其他CPU核心也需要初始化trap和plic
kvm_inithart();
trap_kernel_inithart();   // 初始化当前核心的trap
plic_inithart();          // 初始化当前核心的PLIC

// 使能中断
intr_on();
```

**说明**:

- 其他 CPU 只需要初始化每个核心独立的资源
- 不需要再次调用全局初始化函数（uart_init, plic_init, trap_kernel_init）

## 初始化流程图

```
系统启动
    ↓
entry.S (汇编入口)
    ↓
start.c: start() [M-mode]
    ├─ 配置特权级
    ├─ 委派中断/异常到 S-mode
    ├─ 配置物理内存保护
    ├─ timer_init() ←─── 【新增】初始化 M-mode 时钟中断
    └─ mret → 切换到 S-mode
    ↓
main.c: main() [S-mode]
    ↓
CPU 0 (主CPU):
    ├─ print_init()
    ├─ pmem_init()
    ├─ kvm_init()
    ├─ kvm_inithart()
    ├─ uart_init() ←────────── 【新增】初始化串口
    ├─ plic_init() ←────────── 【新增】初始化 PLIC (全局)
    ├─ trap_kernel_init() ←─── 【新增】初始化 trap (全局)
    ├─ trap_kernel_inithart() ← 【新增】初始化 trap (核心)
    ├─ plic_inithart() ←────── 【新增】初始化 PLIC (核心)
    ├─ intr_on() ←──────────── 【新增】使能中断
    └─ 继续执行用户代码...
    ↓
其他 CPU (CPU 1, 2, ...):
    ├─ 等待 CPU 0 完成全局初始化
    ├─ kvm_inithart() ←─────── 【新增】虚拟内存初始化
    ├─ trap_kernel_inithart() ← 【新增】初始化 trap (核心)
    ├─ plic_inithart() ←────── 【新增】初始化 PLIC (核心)
    ├─ intr_on() ←──────────── 【新增】使能中断
    └─ 继续执行用户代码...
```

## 中断处理准备完成后的系统状态

### M-mode 状态

- mtvec 指向 timer_vector
- CLINT_MTIMECMP 已设置
- mscratch 已配置
- MIE.MTIE = 1 (时钟中断使能)
- MSTATUS.MIE = 1 (M-mode 中断使能)

### S-mode 状态 (每个 CPU)

- stvec 指向 kernel_vector
- SIE.SEIE = 1 (外设中断使能)
- SIE.SSIE = 1 (软件中断使能)
- SIE.STIE = 1 (时钟中断使能)
- SSTATUS.SIE = 1 (S-mode 中断使能)

### 设备状态

- UART 已初始化并使能中断
- PLIC 已配置中断优先级和使能位
- 系统时钟 (ticks) 已初始化

## 中断处理流程验证

### 时钟中断流程

```
CLINT 时钟到期
    ↓
触发 M-mode 时钟中断
    ↓
timer_vector (trap.S) ←─── mscratch 提供临时空间
    ├─ 保存寄存器
    ├─ 更新 CLINT_MTIMECMP
    ├─ 设置 SIP.SSIP (触发 S-mode 软件中断)
    └─ mret 返回
    ↓
触发 S-mode 软件中断
    ↓
kernel_vector (trap.S) ←─── stvec 指向此处
    ├─ 保存所有寄存器
    ├─ call trap_kernel_handler()
    │       ↓
    │   timer_interrupt_handler()
    │       ├─ 清除 SIP.SSIP
    │       ├─ timer_update() (ticks++)
    │       └─ printk("Timer interrupt...")
    │       ↓
    ├─ 恢复所有寄存器
    └─ sret 返回
```

### UART 中断流程

```
UART 接收到数据
    ↓
触发 PLIC 中断请求
    ↓
触发 S-mode 外设中断
    ↓
kernel_vector (trap.S)
    ├─ 保存所有寄存器
    ├─ call trap_kernel_handler()
    │       ↓
    │   external_interrupt_handler()
    │       ├─ plic_claim() → 获取 IRQ
    │       ├─ uart_intr() → 处理串口数据
    │       └─ plic_complete(IRQ)
    │       ↓
    ├─ 恢复所有寄存器
    └─ sret 返回
```

## 关键函数调用时序

```
时间轴 (从系统启动开始):

T0: entry.S 启动
T1: start() [M-mode]
    └─ timer_init() ←─── 在这里初始化 M-mode 时钟
T2: mret → 切换到 S-mode
T3: main() [S-mode, CPU 0]
    ├─ uart_init()
    ├─ plic_init()
    ├─ trap_kernel_init()
    ├─ trap_kernel_inithart()
    ├─ plic_inithart()
    └─ intr_on() ←───────── 从这里开始可以接收中断
T4: 其他 CPU 启动
    ├─ trap_kernel_inithart()
    ├─ plic_inithart()
    └─ intr_on()
T5: 第一个时钟中断到达 (约 0.1 秒后)
T6: 后续中断持续产生...
```

## 注意事项

1. **初始化顺序很重要**: 必须先初始化设备，再初始化中断控制器，最后使能中断
2. **多核同步**: CPU 0 需要完成全局初始化后，其他 CPU 才能启动
3. **中断嵌套**: 默认在中断处理中关闭中断，避免嵌套
4. **锁保护**: timer_update() 使用自旋锁保护，确保多核安全
